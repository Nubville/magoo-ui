# Magoo — plan

A UI library of CSS-only custom elements (`<mg-badge>`, `<mg-card>`, …) with Storybook docs.
Named for Mr. Magoo: it stumbles past every browser hazard and comes out fine. Every component
has an old-school baseline, and newer platform features enhance it where supported.

Inspiration: https://dev.to/stuffbreaker/css-only-custom-elements-go6

## Principles

1. **No build for the library.** Raw CSS (and optional ESM) ships as-is. Storybook is dev-only tooling.
2. **One directory per component.** CSS, stories and optional JS live together.
3. **Undefined custom elements + CSS.** Tag names are the vocabulary, attributes are variants, `slot="…"` attributes are layout hooks, custom properties are the public API.
4. **Baseline first, enhance second.** Fallback declarations first, then modern ones (`color-mix`, `light-dark`, anchor positioning, `@scope`) via cascade order or `@supports`.
5. **Native elements do the semantics.** Wrap real `<button>`, `<dialog>`, `<details>` and inputs. Never fake roles or form behavior.
6. **JS is the last tier and optional.** Only for behavior CSS and the platform can't cover, and the CSS must still work without it.

## Conventions

- Prefix `mg-`. Library and repo name is "Magoo".
- Layers declared once: `@layer mg.tokens, mg.base, mg.components, mg.enhanced;`. Consumers' unlayered CSS always wins.
- Public custom properties: `--mg-<component>-<thing>`. Private: `--_<thing>`. Use `@property` for typed tokens.
- Slots: use child combinators (`mg-card > [slot="header"]`) so nested components don't collide.
- No `order` to reorder content (breaks focus order). DOM order equals visual order; use grid areas.
- Document with JSDoc in the CSS (attributes, slots, CSS properties) for the CEM analyzer.

## Layout

```
magoo/
  components/
    mg-badge/
      mg-badge.css
      mg-badge.stories.js
      mg-badge.js            # optional
  tokens/tokens.css
  index.css                  # @import of layers + all components
  custom-elements.json       # generated by the CEM analyzer (dev script)
  .storybook/
  package.json               # devDependencies only
```

## Steps

1. **Scaffold.** `package.json` (dev deps only), Storybook with `@storybook/web-components-vite`, `staticDirs` pointing at the repo so stories load the real `index.css` via `<link>`.
2. **Foundation.** `tokens/tokens.css` (color, space, type, radius; light and dark via `light-dark()` with a fallback), layer declaration, minimal base.
3. **Component 1: `mg-badge`.** Variants via attributes, custom-property API, baseline vs. enhanced color handling. Proves the token and layer setup.
4. **Component 2: `mg-card`.** Named slots (media, header, body, footer) on grid areas, nesting-safe selectors, compact boolean attribute. Proves composition.
5. **Component 3: `mg-dialog`.** Wraps native `<dialog>` and the `popover` / invoker-command approach. Proves the native-wrapping approach and shows where an optional JS tier is needed.
6. **Docs pipeline.** CEM analyzer with CSS detection, `setCustomElementsManifest` in Storybook, autodocs showing attributes, slots and CSS properties.
7. **Magoo mode.** Storybook toolbar toggle that renders stories as baseline ("squinting") or enhanced ("glasses on"), which needs the enhancements kept in a separable layer or file. Add the a11y addon.
8. **Review the seams.** Write down what didn't work: `@import` waterfall on the no-build path, a11y gaps, anything that needed JS. Decide whether the idea holds up.

## Open questions

- `@storybook/web-components-vite` (better CEM autodocs, adds lit) vs `@storybook/html-vite` (simpler, weaker docs).
- Distribution: link per-component files, or a single `index.css` with `@import`?
- Browser support floor for the baseline tier.
